# Common Rules

## Project Scope

VRCP は、VRChat API の非公式クライアントと関連サイトを含むモノレポです。

- `desktop/`: Tauri を基盤にしたデスクトップアプリケーション（Rust、React、TypeScript）
- `mobile/`: Expo を基盤にしたモバイルアプリケーション（React Native、TypeScript）
- `pages/`: Astro を基盤にした静的サイト

変更時は対象サブプロジェクトを明確にし、他サブプロジェクトの環境や成果物に影響を与えません。

## Working Rules

- 依頼に必要な最小範囲を変更し、無関係な既存変更を変更、削除、巻き戻しません。
- 生成済みコード、ビルド成果物、依存関係ロックファイルは、依頼または正規の生成手順で必要な場合にだけ変更します。
- コードは **How**、テストコードは **What**、コミットメッセージは **Why** を表現します。
- コードコメントは原則として **Why not**（採用しなかった方法とその理由、制約、例外）だけを簡潔な英語で記述します。自明な動作説明、変更履歴、絵文字は書きません。
- 複雑な処理は責務に合う層とファイルへ配置し、同じロジックを複数箇所に複製しません。
- 実装後は変更内容に見合う検証を行い、実行できない検証があれば理由を報告します。
- コミットメッセージは Conventional Commits 形式の `type: summary` または `type(scope): summary` を使います。

## Handoffs

複数のエージェントまたはセッションで作業を引き継ぐ場合は、目的と完了条件、対象ファイル、変更してよい範囲、実施する検証を伝えます。引き継ぐ側は、変更内容、未解決事項、実行済みの検証結果を簡潔に報告します。

## Completion

- 変更したファイルと生成物の整合性を確認します。
- 最終報告では、変更内容、検証結果、残る制約または注意点を簡潔に伝えます。
